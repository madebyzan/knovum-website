---
title: Structured knowledge
description: Record claims, evidence and questions explicitly, connect them with meaningful relations, and let Knovum check the argument.
---

Notes are good for quick thoughts; an argument needs a sturdier form. Structured knowledge records “what I think”, “why I think so” and “what I don't know yet” separately, then connects them. You can see at a glance which conclusions hold and which still need evidence.

## Six knowledge objects

| Object         | Records                                                                          |
| -------------- | -------------------------------------------------------------------------------- |
| **Claim**      | A statement to be tested, such as “Price is not the main reason people leave”    |
| **Evidence**   | Grounds that support or challenge a statement, usually a passage of the original |
| **Question**   | Something still unanswered                                                       |
| **Decision**   | A choice that has been made, and why                                             |
| **Concept**    | A term or definition everyone needs to share                                     |
| **Experiment** | An attempt to test a claim, and its result                                       |

The quickest way to create evidence: after checking a source in a conversation, use **Extract as evidence**. It appears on the canvas with its location in the original.

## Connect them

Drag from an anchor on one object's edge to another object, or select two objects and choose **Connect**, then pick the **Relation type**:

| Relation                   | Meaning                                     |
| -------------------------- | ------------------------------------------- |
| Supports / Contradicts     | Evidence supports or argues against a claim |
| Answers                    | Something answers a question                |
| Depends on                 | One statement presupposes another           |
| Supersedes                 | A newer conclusion replaces an older one    |
| Derives from / Caused by   | Origin and cause                            |
| Reference / Related / Uses | General connections                         |

A line on its own proves nothing. Use **Why these are connected** to write down why the two belong together; you will thank yourself in a few weeks.

## Mark the status

Every object has a **Knowledge status**: **Draft**, **Accepted**, **Contested**, **Superseded** or **Invalidated**; questions are **Open** or **Resolved**. Status gives each conclusion in the Space a clear level of maturity.

## Knowledge checks

Open **Knowledge checks** and Knovum scans the current Space for what needs attention:

- A claim lacks a **Supports** relation.
- An accepted claim has an active **Contradicts** relation.
- Evidence lacks a valid provenance source.
- An open question already has an answer relation.
- A cited source version has changed and needs re-verification.

These are prompts to review, not verdicts on what is true. Work through them and your conclusions get steadily firmer.

## Version history

Each knowledge object keeps a **Knowledge version history**: when it was created, accepted or contested, and who changed it. To trace how a conclusion came about, start here.

## Custom types

When six objects aren't enough, use **New type** in **Manage knowledge types** and add fields: text, number, boolean, date, single-choice enum, or a reference to another node. For example, a “User interview” type with “Interviewee”, “Date” and “Industry”.
