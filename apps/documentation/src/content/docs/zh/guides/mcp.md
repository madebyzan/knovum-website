title: MCP 与扩展
description: 用插件、技能和 MCP 连接，让对话里的 Agent 能查 GitHub、Notion 等外部资料，权限始终由你控制。
---

扩展让对话里的 Agent 多一些本事：按固定流程整理会议纪要，查阅 GitHub 仓库，或者调用你自己的 MCP 服务。所有扩展都在一个地方管理：设置里的「智能能力 → 扩展」。

| 类型     | 是什么                                                 |
| -------- | ------------------------------------------------------ |
| **插件** | 一整套能力，可能包含技能、MCP 服务和应用，作为整体启用 |
| **技能** | 一份指令，告诉 Agent 某类任务该怎么做                  |
| **MCP**  | 一个提供工具和资源的服务，例如数据库或内部系统         |
| **应用** | 随插件提供的外部账号连接，例如 GitHub、Notion、Linear  |

## 在对话里使用

在「对话」的「对话扩展」里，为这次对话选择插件、个人技能或单独的 MCP 连接。选中插件，它包含的技能和服务会一起生效。

启用只表示「允许被选用」。Agent 真正要访问外部服务时，仍会弹出「外部操作需要授权」，由你「允许」或「拒绝」。

## 插件

Knovum 自带八个插件，标为「应用内置」：知识整理、证据研究、会议纪要、文档交付、学习辅导，以及 GitHub、Notion、Linear 工作流。

安装更多插件：

1. 在「发现插件」里浏览插件目录，或点「从来源安装」，选择本地目录或远程地址。来自 Git 的插件可以指定「Git 引用」和「包所在子目录」。
2. 点「预览」，在「确认安装内容」里查看它包含哪些能力。
3. 确认无误后点「安装」。

安装不会启动任何服务，也不会授权任何账号，连接和工具权限需要另外配置。之后可以「检查更新」，更新前同样会列出新增和移除的组件。

:::caution[留意来源]
标有「发布者身份未验证」的插件，安装前请确认来源可信。插件里的指令会影响 Agent 的行为，名字熟悉不代表内容可信。
:::

## 技能

在「技能」里「创建 Skill」，写下「指令内容」；或者「导入目录」，使用已有的 Skill 文件夹。插件自带的技能由插件统一启停，想单独修改，先「复制为个人 Skill」。

## 添加 MCP 服务

1. 在「MCP」里点「添加 MCP 服务」，填写服务名称。
2. 选择「传输方式」：
   - 本地程序：选择已安装服务的可执行文件（绝对路径），逐项填写「参数」。每一项就是一个完整参数，不经过 shell 解析。
   - HTTP：填写「服务器地址」。访问本机或局域网地址时，需要开启「允许访问配置的本机或局域网地址」。
3. 选择「授权方式」：「无需授权」、敏感请求头与环境变量，或者 OAuth。令牌等凭据在保存后单独填写，不要写进普通配置里。
4. 「添加连接实例」，点「检查连接并读取目录」，确认能看到服务提供的工具和资源。

## 控制工具权限

每个连接的「工具权限」里，所有工具默认是「拒绝」。逐个设置「调用策略」：

- **拒绝**：Agent 不能调用。
- **每次确认**：每次调用前问你。
- **允许**：直接调用。

对确实只读的工具，勾选「已确认此工具只读」。研究类任务只能使用你确认过只读的工具。服务端自己声明的「只读」仅供参考，判断由你来做。

## 费用

外部服务可能另行计费，这部分不计入 Knovum 的 Token 用量。
