---
title: 结构化知识
description: 把观点、证据和问题明确记下来，用有含义的关系连起来，让 Knovum 帮你检查论证。
---

便签适合随手记，论证需要更严谨的形式。结构化知识把「我认为什么」「凭什么这么认为」「还有什么不知道」分开记录，再用关系连起来。这样一眼就能看出哪个结论站得住，哪个还缺证据。

## 六种知识对象

| 对象     | 记录什么                                     |
| -------- | -------------------------------------------- |
| **观点** | 一个待检验的判断，例如「价格不是流失的主因」 |
| **证据** | 支持或质疑某个判断的依据，通常是一段原文     |
| **问题** | 还没有答案的疑问                             |
| **决策** | 已经做出的选择，以及为什么                   |
| **概念** | 需要统一理解的术语或定义                     |
| **实验** | 用来验证观点的尝试和结果                     |

最快的建证据方式：在对话里核对完一条来源后，用「摘录为证据」，它会带着原文位置出现在画布上。

## 用关系连起来

拖动一个对象边缘的锚点连到另一个对象，或选中两个对象后「建立关联」，再选择「关系类型」：

| 关系               | 含义                   |
| ------------------ | ---------------------- |
| 支持 / 反证        | 证据支持或否定一个观点 |
| 解答               | 某项内容回答了一个问题 |
| 依赖               | 一个判断以另一个为前提 |
| 替代               | 新的结论取代了旧的     |
| 派生自 / 归因      | 来源关系与因果关系     |
| 引用 / 相关 / 使用 | 一般性的关联           |

一条线本身不是证明。用「关联说明」写下这两者为什么相关，几周后的你会感谢现在的自己。

## 标记状态

每个对象都有「知识状态」：「草稿」「已确认」「有争议」「已被替代」「已失效」，问题则是「待解决」和「已解决」。状态让空间里的结论有了明确的成熟度。

## 知识检查

打开「知识检查」，Knovum 会扫描当前空间，列出需要处理的地方：

- 观点缺少「支持」关系。
- 已确认的观点存在「反证」。
- 证据没有可追溯的来源。
- 问题已经有了解答，却仍是待解决。
- 引用的来源版本已变更，需要重新核对。

这些是复核提示，不是对真假的裁决。逐条处理，你的结论就会越来越扎实。

## 版本历史

每个知识对象都记录「知识版本历史」：何时创建、何时被确认、何时出现争议、谁做了修改。需要回溯一个结论是怎么形成的，从这里看。

## 自定义类型

六种对象不够用时，在「管理知识类型」里「新建类型」，为它添加字段：文本、数值、布尔值、日期、单选枚举，或引用另一个节点。例如为「用户访谈」类型加上「受访者」「日期」「行业」三个字段。
